## 通常の正文からスタート

優れた閲覧体験は、主張しすぎないものです。正文（本文）に適度な行幅を保ち、段落間に十分な余白（呼吸）を与え、リンクや強調、注釈を文章の中に自然に溶け込ませます。例えば、[Astro 公式サイト](https://astro.build/) を訪れることもできますし、**太字で重要ポイントを強調** したり、*斜体でニュアンスを表現* したり、`行内コード` を使ってファイル名やコマンドを明示することもできます。

日本語や English、数字の 2026、シンボル `@astrojs/mdx` が混在してレイアウトされても、文字は安定して読みやすく保たれるべきです。長めの段落は、行高（行間）と改行の具合を観察するのに適しています。デザインとはあらゆるものを複雑に装飾することではなく、読者がコンテンツの中に階層構造を見つけ、立ち止まるべき場所で立ち止まり、先へ進むべき場所で自然に進めるよう手助けすることです。

> 優れたテーマは、記事そのものへの集中を削ぐことがありません。
> それは静かな展示室のようなものです。光、距離、方向をコントロールし、ステージをコンテンツ自身に譲ります。

### テキストのディテール

以下に、よく使われるインライン要素を集めました：

- **これは太字です**。結論やキーワードに適しています。
- *これは斜体です*。ニュアンスや作品名に適しています。
- ~~これは打ち消し線です~~。修正前のアイディアを示すのに適しています。
- `const theme = 'ulBo'` は行内コードです。
- [これは外部リンクです](https://docs.astro.build/)。ホバー時や訪問済みの状態を確認できます。

## リストと情報の階層構造

リストは長文の中で最も一般的な構造のひとつです。箇条書き（順不同リスト）は並列する情報に適しています：

- 明確なコンテンツ階層
- 快適な読書幅
- 安定した目次の位置指定
  - ネストされた項目（レベル2）も容易に識別できるべきです
  - インデントが本文のテンポを崩してはいけません
- モバイルフレンドリーなインタラクション

番号付きリスト（順序付きリスト）は、手順を説明するのに適しています：

1. 記事の最も重要な結論を書く。
2. 見出しを使って明確な章を立てる。
3. 根拠として画像、コード、またはデータを追加する。
4. 最後にモバイル環境での閲覧体験をチェックする。

タスクリストで完了状態を示すこともできます：

- [X] 記事の構造を準備する
- [X] オリジナルのデモ画像を追加する
- [X] 主要な Markdown スタイルをカバーする
- [ ] あなただけの次の記事を書く

### なぜ画像のサイズ指定が重要なのか

ブラウザが画像をダウンロードする前にその縦横比を知っていれば、あらかじめ正しいスペースを確保でき、コンテンツが突然ガタつく（レイアウトシフト）のを防げます。当サイトの Markdown 画像処理はサイズ情報を補完し、遅延読み込み（Lazy Load）を使用してファーストビューの速度とスクロール体験のバランスをとっています。

> **ヒント**：目次の追従機能をテストする際は、後続の「コード表示」や「数学公式」の章をクリックしてから、上下に素早くスクロールして、ハイライト状態と最終的な停止位置を確認してみてください。

## コード表示

行内コードは `npm run dev` のような短い内容に適しています。一方、コードブロック全体はシンタックスハイライト、横スクロール、長文の折り返しを表示するために使用します。

```ts
type Post = {
  title: string;
  description: string;
  tags: string[];
};

const featuredPost: Post = {
  title: 'Designing a calm reading experience',
  description: 'Content first, decoration second.',
  tags: ['Astro', 'Design', 'Markdown'],
};

export const formatTitle = ({ title }: Post) =>
  `${title} — ulBo`;
